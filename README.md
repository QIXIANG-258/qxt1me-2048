# 05-game-2048 · 2048 小游戏

> 憩想（QX_t1me）站群的第 5 个模块 —— 一个纯静态、零依赖的 2048。
> 建立于 2026-10-07，当日部署上线：**https://qxt1me-2048.2088801789.workers.dev**

## 是什么

一个标准玩法的 2048：方向键 / WASD 或手指滑动，把相同数字合成 2048。
配色沿用站群家族的**界面零彩度**原则 —— 数字方块从中性灰随数值缓缓升温到黄铜 / 金，彩度只留给数值本身。

- **零依赖**：没有构建步骤，`src/` 里就是最终产物，直接部署。
- **零第三方 JS**：原生 DOM + CSS 动画，不引任何框架。
- **进度不丢**：局内状态、最高分、明暗主题、中英语言都存 `localStorage`，刷新页面接着玩。
- **可撤销**：一步撤销（分数与棋盘一起回退）。

## 操作

| 动作 | 键盘 | 手柄 |
|---|---|---|
| 移动 | 方向键 / `W` `A` `S` `D` | 十字键 D-pad |
| 重开 | `R` | `Y` |
| 撤销 | `C` | `B` |

> ⚠️ **撤销键为什么是 `C` 不是 `D`**：`D` 是 WASD 里的「右移」，
> 抢过来会让 WASD 缺一条腿。改键前先确认新键没被移动键占掉 ——
> 冒烟测试里有一条专门守着这个（「D 键仍然是右移」）。

除键盘外也支持鼠标拖动与手指滑动。

### 冒烟（29 条）

原理值得一提：**它不复制一份算法另写一遍**，而是给 `src/js/app.js` 造一套最小 DOM stub，
让**真实的源码**在 node 里跑起来，再通过 DOM 反读棋盘与分数。重点覆盖：

- 一行四连 `2 2 2 2` 左移 → `4 4`（而不是 `8`）
- `4 4 8` 左移 → `8 8`（同一方块不能在一次移动里合并两次）
- 无效移动不生成新方块、不加分
- 棋盘填满但四向皆堵 → 判负；满盘但有可合并对 → 不判负
- 撤销后棋盘与分数回到上一步
- `1024+1024` 必须触发胜利浮层
- **`R` 重开 / `C` 撤销**，以及 `D` **必须**仍是右移（防止以后改键把 WASD 弄缺）

### 浏览器探针（40 条）

真实 CDP 事件（不是 JS 合成的），含：几何对齐、键盘、鼠标拖动、触摸滑动、
主题对比度、语言、存档、手机视口、手柄。

> 手柄是**注入虚拟 Gamepad** 测的（没真手柄可插），并且专门验了
> 「按住不放只触发一次」—— 手柄靠 rAF 轮询，边沿判断写错会一帧连发几十次。

## 部署

与 `02-universe` / `03-gear` **同形态**：无构建步骤，`src/` 即产物。

```powershell
npx.cmd wrangler@4 deploy --dry-run   # 干跑，看会上传哪些文件
npx.cmd wrangler@4 deploy             # 正式部署
```

⚠️ 本机 `npx` 会被 PowerShell 脚本策略拦（`npx.ps1 cannot be loaded`），**用 `npx.cmd` 而不是 `npx`**。

⚠️ `wrangler.jsonc` 里的 `name` 必须和 Cloudflare 控制台里的 Worker 名完全一致，否则构建直接失败。

**部署现状（2026-10-07）**：已上线，Worker 名 `qxt1me-2048`，
预览地址 https://qxt1me-2048.2088801789.workers.dev 。

自定义域名建议走控制台：Worker → 设置 → 域和路由 → 添加 → 自定义域（`2048.qxt1me.dpdns.org`）。

$env:PROBE_URL = "https://qxt1me-2048.2088801789.workers.dev"

固定 `--no-proxy-server` 会让 `Page.navigate` 直接超时。打本地地址则自动用直连。

### 改版后访客看不到新版？

`css/js` 是**裸引用**（不带 `?v=` 指纹），`_headers` 给的是 `max-age=300`。
所以改完最多等 5 分钟，或者强刷。字体是一年 `immutable` —— 文件名是语义名、内容不变，换字体就换文件名。

## 几个设计取舍

**为什么方块常驻 DOM，而不是每步重建？**
2048 的「灵动」几乎全在滑动动画上。每步重建 DOM 的话，方块的位置记忆丢失，只能靠「重新播放入场动画」伪造运动感。
这里让 16 个方块常驻，只改 CSS 自定义属性 `--x` / `--y`，滑动交给 `transform` 过渡 —— 位移是**真的位移**。

**为什么合并要分两步（先滑、后翻倍）？**
如果合并瞬间就把值翻倍，玩家会看到「一个 4 从原地凭空出现」。
正确观感是：两个 2 滑到同一格 → 合二为一 → 弹一下变成 4。所以被吸收的方块先滑过去（动画结束后移除），
存活方块的翻倍推迟到滑动动画收尾时再写回。

**`SLIDE_MS` 和 CSS 的 `--slide` 必须一致**
`js/app.js` 里的 `SLIDE_MS` 是动画收尾的延时，`css/style.css` 里的 `--slide` 是过渡时长。
改一个必须改另一个，否则会出现「数字还没到位就翻倍」或者「停顿明显」。
